# 知行：企微外部客户群 + Dify RAG 测试闭环

这个仓库把已经跑通的测试链路整理成可复现、可脱敏的版本：普通微信成员在企业微信外部客户群中发送带触发词的问题，非官方企微客户端内核接收消息，本地适配层调用 Dify 知识库应用，再把答案发回原群。

> [!CAUTION]
> 这不是企业微信官方外部群机器人 API。消息收发依赖第三方、未签名的 `newqi24.exe` 及其客户端 Hook/注入行为，存在账号风控、封禁、升级失效、隐私泄露和终端安全风险。仓库仅用于隔离的测试账号、测试群、虚构知识库和专用测试机，不代表可直接生产上线。

## 已验证的链路

```text
企微外部客户群
→ newqi24.exe（固定企微版本 4.1.33.6009）
→ 127.0.0.1:8765 本地 Dify 适配层
→ Dify Cloud Chat API / RAG 知识库
→ 原群自动回复
```

2026-08-13 的本机测试中，普通微信成员发送 `AI答疑助手 星河计划什么时候截止报名？`，原群收到基于测试知识库生成的答案；适配层健康检查正常，Dify 返回 HTTP 200。不同成员、不同群的上下文隔离仍需单独验收。

## 仓库包含什么

- `adapter/dify_proxy.py`：只监听 `127.0.0.1` 的 Dify Cloud 转发层，不记录问题、答案或 API Key。
- `scripts/`：下载校验第三方内核、配置防火墙、启动、停止、状态检查和本地验证脚本。
- `.env.example`：不含凭证的配置模板。
- `examples/`：纯虚构测试知识库与验收问题。
- `new-kernel-runtime/trigger_words.json`：触发词模板。

仓库明确不包含 `.env`、Dify/模型供应商 Key、聊天记录、群/成员标识、SQLite 数据库、日志、企微安装包、内核二进制、FFmpeg 或上游发布包。原因和校验值见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 最小闭环部署

### 1. 准备隔离环境

- Windows 10/11 测试机或专用虚拟机。
- Python 3.10 或更高版本，执行 `python --version` 能看到版本号。
- 测试企业微信成员账号、测试外部群、一个普通微信测试账号。
- 不要使用主账号、真实客户群或真实公司制度做首次验证。

### 2. 准备 Dify 应用

按 [Dify 配置说明](docs/DIFY_SETUP.md)创建 Chat/Chatflow 应用、导入虚构知识库并取得应用 API Key。Key 通常以 `app-` 开头；OpenAI 等模型供应商的 `sk-` Key 应配置在 Dify 的模型供应商页面，不应填到本项目中。

### 3. 安装固定版本企业微信

下载腾讯官方的 `WeCom_4.1.33.6009.exe`，确认数字签名有效后安装到独立目录。已验证路径是 `D:\WXWork\WXWork.exe`，其他路径可在 `.env` 中修改。

官方下载地址和已验证 SHA-256 见 [THIRD_PARTY.md](THIRD_PARTY.md)。请关闭自动更新；升级到其他企微版本后，第三方内核可能失效或触发风控。

### 4. 下载并校验第三方内核

先阅读 [SECURITY.md](SECURITY.md)，确认只在测试环境承担风险，然后在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-runtime.ps1 -AcceptRisk
```

脚本从上游 GitHub Release 下载 314 MB 发布包，校验整个 ZIP，只提取并再次校验 `newqi24.exe`。上游包中的数据库、消息 CSV、图片和日志不会被解压。

### 5. 写入本地配置

```powershell
Copy-Item .env.example .env
notepad .env
```

至少修改：

- `DIFY_API_KEY=app-...`
- `WECOM_EXE_PATH=你的固定版本 WXWork.exe 路径`

`.env` 已被 `.gitignore` 排除，任何情况下都不要提交它。

### 6. 配置入站防火墙

双击 `配置内核防火墙.cmd`，接受管理员权限。第三方内核会监听 `0.0.0.0:8002`，本规则会阻止局域网或公网直接访问该程序；本机回环健康检查仍可使用。

### 7. 启动并测试

1. 先停止旧测试目录中的同类内核和适配层，避免端口冲突。
2. 双击 `启动企微Dify测试.cmd`。
3. 在打开的企业微信中登录专用测试成员账号。
4. 由该成员创建外部客户群，并让普通微信测试账号扫码入群。
5. 普通微信发送：`AI答疑助手 星河计划什么时候截止报名？`
6. 预期原群回复包含 `2026年8月20日18:00`，并明确说明信息来自测试知识库。
7. 双击 `检查企微Dify状态.cmd` 查看适配层、内核、企微版本、防火墙和心跳。
8. 测试结束后双击 `停止企微Dify测试.cmd`。

更多用例见 [测试问题清单](examples/测试问题清单.md)。

## Dify 与费用的关系

群消息调用的是 Dify 应用 API。知识库检索、模型生成和额度结算都由该 Dify 应用的配置决定：

- 使用 Dify Cloud 免费额度时，消耗 Dify Cloud 的 AI 消息额度。
- 在 Dify 中配置自己的 OpenAI 或其他模型供应商 Key 后，由相应供应商计费。
- 本项目 `.env` 中的 `DIFY_API_KEY` 只是 Dify 应用调用凭证，不是模型供应商 Key。

## 常见问题

**提示 DIFY_API_KEY 看起来像模型供应商 Key**
你填了 `sk-...`。请到 Dify 应用的“访问 API / API 密钥”页面复制 `app-...`；模型 Key 留在 Dify 的模型供应商设置中。

**启动时提示企业微信版本不一致**
脚本会拒绝非 `4.1.33.6009` 版本。不要仅修改版本号绕过检查；Hook 点和客户端结构可能已经变化。

**适配层端口已占用**
先双击旧目录和本目录的停止脚本，再检查 `127.0.0.1:8765`。不要让两个测试实例共享同一端口。

**`/all-groups` 返回 500**
已验证的原群问答不依赖该接口，而是使用收到消息携带的 `room_id` 回原群；不能据此单独判断消息闭环失败。

**客户问了但机器人没答**
先确认消息含 `AI答疑助手` 或 `@AI答疑助手`，再运行状态检查；同时检查 Dify 应用是否已发布、Key 是否属于该应用、额度是否充足。

## 生产化边界

投入真实业务前至少需要完成：专用账号/专用机、客户告知与合规评审、日志脱敏与保留周期、客户/群/知识类型权限隔离、提示词注入与敏感信息拦截、无依据拒答、答案出处、低置信度转人工、重复消息防护、并发与稳定性测试、额度告警和账号风控预案。

即使补齐这些控制，客户端 Hook/注入本身的账号与合规风险也不会消失。若风险不可接受，只能改用企业微信官方允许的会话入口，而无法同时保证在原外部群消息流内全自动双向问答。
